# 工作项状态流转与负责人

默认状态为：待规划、待开始、开发中、开发完成/待验收、已完成、已取消。开发中和开发完成/待验收都属于原有的进行中分组，因此报表仍会把待验收工作项计入未完成工作。

在工作项详情页或快速预览页的“各状态负责人”中，可以为每个状态选择一个或多个项目成员。例如，将“开发中”分配给 A，将“开发完成/待验收”分配给 B。A 把工作项转入待验收后，当前负责人自动变为 B；B 可以继续处理或退回开发。

- 未单独配置的状态沿用流转前的当前负责人。
- 显式清空某个状态的负责人后，进入该状态会变为未分配。
- “恢复沿用”移除该状态的单独配置。
- 若当前状态已单独配置，修改工作项当前负责人会同步更新该配置。
- 新工作项可以先创建，再配置各状态负责人。

普通项目成员仅能流转当前由自己负责的工作项。仅是后续状态的负责人、创建者或其他参与者，不会获得当前状态的处理权限。项目管理员、拥有项目成员身份的工作空间管理员，以及有成员权限的项目负责人可以跨负责人处理；PM 可使用这些现有项目管理角色。

负责人配置同样受到权限校验，避免无关成员先把工作项指派给自己再流转。当前状态没有负责人时，创建者可以先配置负责人，但不能在同一次请求中通过自指派获得流转权限。访客和已停用成员不具备流转权限。

流转请求在数据库事务内锁定工作项，并依据数据库中的当前状态和负责人进行校验。同一工作项的状态变更、当前负责人和状态负责人配置一起保存；请求失败时不会保留部分修改。批量界面仍按现有方式逐项提交，每一项独立校验。

## 升级与接口

部署时需执行 API 数据库迁移并发布前端构建。数据迁移原地更新旧默认英文状态名称，保留状态 ID 与已有工作项关联，并为由默认 In Progress 转换来的“开发中”补上待验收状态。自定义、导入和已删除状态保留；遇到目标中文名称已存在时，不合并或覆盖该状态。

工作项增加 `state_assignees` 字段，格式为状态 UUID 到用户 UUID 数组的映射：

```json
{
  "state_assignees": {
    "<开发中状态 UUID>": ["<A 的用户 UUID>"],
    "<待验收状态 UUID>": ["<B 的用户 UUID>"]
  }
}
```

提交该字段会替换整张配置映射。状态必须属于当前项目，负责人必须是当前项目的有效成员。普通工作项的状态配置不包含收件箱的分诊状态。

应用接口使用 `state_id`、`assignee_ids`；外部 API 使用 `state`、`assignees`。两类接口都支持 `state_assignees`，并在服务端校验流转权限。配置修改和流转成功后，前端同步服务端返回的实际状态与负责人。
