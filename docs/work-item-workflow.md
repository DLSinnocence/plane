# 工作项状态流转与负责人

默认状态为：待规划、待开始、开发中、开发完成/待验收、验收完成/待测试、已完成、已取消。开发中、开发完成/待验收和验收完成/待测试都属于原有的进行中分组，因此报表仍会把待验收、待测试工作项计入未完成工作。

项目状态配置为只读：项目设置仅展示状态，不提供新增、编辑、删除、排序或修改默认状态操作；应用接口和外部 API 同样不接受状态配置写入。工作项仍可按权限在适用状态之间流转。升级保留已有状态及工作项关联，不自动删除历史自定义状态。

工作项属性增加“需要测试”，新建及历史工作项默认是，草稿也保留该属性。选择否时，该工作项的状态选择和阶段负责人配置不显示“验收完成/待测试”；选择是时重新显示。测试阶段通过状态的 `is_testing` 标记识别，重命名不影响此规则。当前已在测试阶段时，需先流转到其他状态再关闭“需要测试”；接口也允许在一次请求中同时关闭该属性并切换到非测试状态，不会自动跳转或完成工作项。

在新建工作项、详情页或快速预览页的“各阶段负责人”中，可以为待开始、开发中、开发完成/待验收等处理阶段选择一个或多个项目成员。每个阶段均明确默认选择工作项创建者。例如，将“开发中”分配给 A，将“开发完成/待验收”分配给 B。A 把工作项转入待验收后，当前负责人自动变为 B；B 可以继续处理或退回开发。

- 新建表单隐藏原有的单一负责人选择，只提供各处理阶段的负责人配置。
- 待规划、已完成、已取消阶段（包括这些分组中的自定义状态）不显示负责人选择器，固定由创建者负责。
- 各阶段独立保存负责人，不沿用流转前的当前负责人。历史工作项或新增加的阶段缺少配置时，也默认由有效创建者负责；创建者不再是有效项目成员时默认未分配。
- 显式清空可配置阶段的负责人后，进入该阶段会变为未分配。
- “设为创建者”将该处理阶段明确指派给创建者。
- 当前负责人是所在阶段配置的结果，详情、预览、列表等位置仅供查看；不允许通过独立负责人字段、快捷操作、拖拽或接口手动改派。需要调整时，由所有者或管理员修改对应处理阶段的负责人配置。
- 切换项目、连续创建和保存草稿都按当前项目的阶段生成明确配置。

普通项目成员仅能流转当前由自己负责的工作项。仅是后续状态的负责人、创建者或其他参与者，不会获得当前状态的处理权限。项目管理员、拥有项目成员身份的工作空间管理员，以及有成员权限的项目负责人可以跨负责人处理；PM 可使用这些现有项目管理角色。

负责人配置与状态流转使用独立权限。仅工作项所有者或管理员可以配置可调整阶段的负责人，当前负责人随该配置或阶段变化自动同步。工作项所有者使用现有的 `created_by`（创建者）字段识别，没有独立的 `owner` 字段；所有者必须是有效项目成员，角色至少为 MEMBER（15）。管理员包括项目管理员，以及已加入该项目的工作空间管理员。当前状态负责人不能仅凭负责身份修改任何指派；MEMBER 角色的项目负责人只能按项目管理人员权限流转状态，除非同时是工作项所有者或管理员，否则不能配置负责人。

所有者在工作项已有负责人时仍可配置指派；所有者身份本身不授予流转权限。状态流转继续依据已持久化的当前责任关系校验，仅当前负责人或项目管理人员可操作，不能通过同一次请求中的自指派获得权限。访客、无项目成员身份及已停用成员不具备配置或流转权限。

流转请求在数据库事务内锁定工作项，并依据数据库中的当前状态和负责人进行校验。同一工作项的状态变更、当前负责人和状态负责人配置一起保存；请求失败时不会保留部分修改。批量界面仍按现有方式逐项提交，每一项独立校验。

## 升级与接口

部署时需执行 API 数据库迁移并发布前端构建。数据迁移原地更新旧默认英文状态名称，保留状态 ID 与已有工作项关联，并为由默认 In Progress 转换来的“开发中”补上待验收状态。自定义、导入和已删除状态保留；遇到目标中文名称已存在时，不合并或覆盖该状态。

本次新增 `0129_draftissue_state_assignees` 迁移，为草稿保存阶段负责人映射。升级时需执行该迁移；重新打开草稿及转成正式工作项会保留已选的阶段负责人。

工作项增加 `state_assignees` 字段，格式为状态 UUID 到用户 UUID 数组的映射：

```json
{
  "state_assignees": {
    "<开发中状态 UUID>": ["<A 的用户 UUID>"],
    "<待验收状态 UUID>": ["<B 的用户 UUID>"]
  }
}
```

提交该字段会替换配置映射，服务端补全未提供的阶段为创建者，并保证固定阶段归创建者负责。状态必须属于当前项目，负责人必须是当前项目的有效成员。普通工作项的状态配置不包含收件箱的分诊状态。

应用接口使用 `state_id`，外部 API 使用 `state`；两类接口都使用 `state_assignees` 配置阶段负责人。返回的 `assignee_ids`（应用接口）或 `assignees`（外部 API）表示当前阶段的实际负责人，更新接口不接受独立修改。服务端校验流转权限，配置修改和流转成功后，前端同步服务端返回的实际状态与负责人。

两类接口均通过布尔字段 `needs_testing` 读写“需要测试”。当该值为 `false` 时，服务端拒绝进入带 `is_testing` 标记的状态。状态接口中的 `is_testing` 为只读字段。关闭测试不会清空已配置的测试阶段负责人，重新开启时可以继续使用原配置。部署该功能需执行新增数据库迁移，为工作项和草稿补上默认值，并为现有项目补充测试状态。
