# 工作项权限与子项显示

## 项目写入权限

| 操作                                         | 项目 admin／具备有效项目成员资格的工作区 admin | 项目 member                                          |
| -------------------------------------------- | ---------------------------------------------- | ---------------------------------------------------- |
| 直接创建正式工作项、子工作项、复制、发布草稿 | 可以                                           | 不可以；通过“接收”提交                               |
| 在“接收”提交工作项                           | 可以                                           | 可以                                                 |
| 审核、接受、拒绝或标记接收项                 | 可以                                           | 不可以                                               |
| 修改工作项内容、状态或属性                   | 可以                                           | 仅自己创建或当前阶段分配给自己的工作项               |
| 上传附件、管理附件行、应用附件模板           | 可以                                           | 仅自己创建或当前阶段分配给自己的工作项               |
| 删除／替换已上传文件                         | 可以                                           | 同时需要工作项写入权限及文件上传者身份               |
| 调整阶段负责人配置                           | 可以                                           | 仅自己创建的工作项                                   |
| 批量修改或调整父子、关联、周期和模块         | 可以                                           | 所有被修改的工作项均需有写入权限；任一无权则整批拒绝 |

所有写入都要求用户仍然是有效的工作区成员和项目成员。项目负责人（lead）身份本身不授予管理其他人工作项的权限。创建人转交工作项后仍保留修改权限；仅因当前阶段分配而获得权限的成员，在转交后不再具有该权限。未来阶段的分配不会提前授予当前阶段写入权限。

权限在服务端按持久化数据判断，网页按钮、直接 API 调用和 AI/MCP 使用相同规则。上传完成时会再次检查权限，不能凭之前获得的上传地址在权限被撤销后发布附件。接收项的内容编辑不会赋予审核或绕过接收直接转为正式工作项的权限。

删除父项时也会检查全部子项和后代工作项的权限；任一无权则拒绝整次操作，不会排队执行级联删除。

## 子工作项显示

工作项列表统一包含子工作项，旧的 `sub_issue: false` 设置不再隐藏它们。“我的工作项／分配给我”中，父项未分配给当前用户时，匹配的子项仍作为独立列表行显示。

列表和表格进入时默认展开子项并自动加载；读取和展开不依赖编辑权限。多层嵌套按列表可显示的层级提升深层根节点，避免子项被隐藏或重复出现。
