# 工作项附件槽位与模板库

在工作项详情的**附件 → 附件槽位**中，可以设置有名称的上传位置，例如“安装包”“测试报告”“设计稿”。每个槽位只显示一个当前附件，普通附件仍可照常上传。

## 使用槽位

- 点击**添加槽位**，输入名称；槽位支持重命名和删除。
- 空槽位点击**上传附件**，已有文件的槽位点击**替换附件**。沿用实例配置的单文件上传上限，默认 1GB（1073741824 字节）。
- 新文件上传并确认成功后才会替换当前附件；上传失败或取消时原附件保留。
- 替换成功后的旧文件会保留为普通附件。删除槽位也只移除槽位，已上传文件会保留为普通附件。
- 点击文件名可下载。删除当前附件后，槽位恢复为空，之后可再次上传。

每个工作项最多 50 个槽位。槽位名称去除首尾空白后需为 1–100 个字符，同一工作项不能存在忽略大小写后的重名槽位。

## 使用工作区模板库

在附件槽位区域点击**模板库**，可以新建、编辑、删除模板，或应用已有模板。模板由同一工作区的项目共用，只保存模板名称和一组按顺序排列的槽位名称，不包含附件文件。

也可以配置好工作项的槽位后，点击**存为模板**，将当前槽位名称保存到库中。

应用模板时只追加工作项中缺少的槽位，保留已有槽位、名称和附件。重复应用同一个模板不会重复创建同名槽位。追加后如果超过 50 个槽位，整次应用会被拒绝，不会只创建一部分。

编辑或删除库中的模板不会追溯修改已应用的工作项。再次显式应用修改后的模板时，也只会补充缺少的槽位。

## 权限与兼容性

模板库供活跃的工作区管理员、成员管理；访客不能访问模板库。槽位管理及上传要求具有对应项目的管理员或成员权限，能查看工作项的访客可以查看槽位。附件下载仍要求工作项访问权限，删除附件沿用项目管理员或文件创建者的权限规则。

新功能用于已创建的工作项；草稿继续使用原有普通附件流程。已有附件不会自动绑定到新槽位，也不会因模板应用而被删除或移动。

## 上传失败时的具体原因

文件选择失败会显示浏览器返回的错误码与说明，并列出文件实际字节数和当前限制。只有文件确实超过限制时才提示大小超限。

上传接口或存储服务失败时，会保留 HTTP 状态码及接口返回的错误说明；S3 兼容存储的 XML 错误只展示错误码和说明，不展示签名请求。权限拒绝、文件类型不支持、网络错误和服务端请求大小限制分别提示，便于判断失败发生在哪里。

普通附件上传权限沿用项目管理员、成员及访客规则，文件大小限制不按这些角色区别设置。若同一文件只有部分成员失败，应依据提示中的实际接口原因核对该成员的项目访问权限和部署配置。

## 部署

部署新版本前执行 API 数据库迁移：

```bash
python manage.py migrate
```

迁移 `0130_attachment_templates_slots` 创建工作区附件模板及工作项附件槽位，并为文件资产增加可空的槽位关联。现有文件保持无槽位关联。前端及 API 需要一起更新。

后台通过事务和数据库约束保证同一槽位只有一个当前已完成附件；模板应用和槽位变更按工作项序列化，避免并发应用创建重名槽位或超过数量上限。
