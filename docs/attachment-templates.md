# 工作项附件与模板库

工作项中的所有附件使用同一种可命名的附件行，每行包含一个名称和至多一个文件。默认名称为“附件”；同名时使用“附件2”“附件3”等。左侧名称可以编辑，中间显示图片预览或文件名，右侧是文件信息与 **⋯** 菜单。

## 添加与上传

- 点击附件标题右侧的 **+**，直接新增空附件行并选中名称；附件区折叠时自动展开。
- 顶部**附加**可直接选择文件。上传后也显示为同样的附件行，自动获得默认名称。
- 点击行中间的**空附件**上传文件；图片附件直接显示缩略图，点击缩略图放大查看，其他附件点击文件名打开原文件。
- 名称可在左侧行内编辑，Enter 或离开输入框保存，Escape 取消。名称为空、重复或保存失败时提示错误并保留输入。
- 附件数量按行计算，空行与有文件的行各计一次，上传进度不会重复计数。
- 新建最多 50 个附件行。名称去除首尾空白后需为 1–100 个字符，同一工作项内不能存在忽略大小写后的重名。已有历史超过 50 个附件时会完整保留，仍可改名、下载和删除。

## PSD 与大文件压缩

- 支持上传 `.psd`／`.PSD` Photoshop 源文件；下载保留原文件和图层，不转换为平面图片。PSD 不提供浏览器内图片预览。
- 网页上传的原文件 **大于 50 MB（52428800 字节）** 时，上传前自动进行 gzip 无损压缩；等于或小于此值保持原样。新增、指定行上传及替换文件共用此流程。
- 浏览器下载时自动还原原文件，保留原文件名、格式和内容，无需手动解压。附件列表显示原文件大小，压缩后的实际大小单独保存；压缩率取决于内容，已经压缩过的文件可能略微变大。
- 大小上限仍按原文件判断，沿用实例配置（默认 1 GB），不能通过压缩绕过上限。浏览器不支持压缩或压缩失败时明确提示，不会误上传损坏的文件。
- 历史未压缩附件保持原下载行为，不会批量改写旧文件。

### 存储与部署说明

工作项 V2 与外部附件 API 的上传预签名请求仍以 `name`、`type`、`size` 表示原文件。压缩上传额外传入 `content_encoding: "gzip"` 与 `compressed_size`，两者必须同时提供。服务端验证原文件上限并按压缩后的实际字节数签名；对象存储 POST 策略同时锁定原始 `Content-Type` 和 `Content-Encoding: gzip`，不增加 `.gz` 后缀。

确认上传时，服务端经内部存储地址流式校验 gzip 完整性、存储元数据和解压后的准确大小；最多读取申报原大小加 1 字节的解压内容，不缓存整个原文件。成功后按源 ETag 条件复制至未被上传签名授权的固定文件键，再事务性完成附件／替换旧文件，提交后清理暂存对象。因此重放原上传签名不会覆盖已验证的附件；校验或复制失败时保留原附件并返回错误。此流程要求存储账号具备读取、复制写入及删除对象权限，较大文件的上传确认会额外消耗校验时间。

现有受保护下载地址继续跳转至 S3／MinIO 签名 GET。对象的 `Content-Encoding` 由浏览器在下载、读取图片或 `fetch` 时自动解码一次；客户端不要再次按响应头手动解压。自定义 API 下载工具应启用 HTTP 内容解码（例如 `curl --compressed`）。压缩对象不支持按**原文件字节位置**进行 Range 断点下载或流媒体定位；当前附件图片预览及完整下载不受影响。

需同时部署 API 和前端，无新增数据库迁移。代理／CDN 必须保留对象存储的 `Content-Encoding` 响应头。新前端在旧 API 未返回正确编码签名时会拒绝发送压缩内容，避免生成无法还原的附件。

## 图片预览

JPG／JPEG、PNG、GIF 或 WebP 附件在附件区只显示缩略图，无需点击即可预览；点击图片可在当前页面放大查看。缩略图按原始比例显示，高度上限约 192px，保留 GIF 动画，下方不再显示文件名或下载按钮。文件名保留在图片悬停提示、无障碍名称及大图标题中。按原始文件名识别格式，不区分扩展名大小写；工作项详情、快速预览、旧附件列表与收件箱卡片使用相同方式。

- 可视区域内的缩略图自动加载，屏幕外图片由浏览器按需加载。加载失败时显示提示，仍可进入大图**重试**或通过菜单**下载**。
- 大图使用深色背景，顶部固定显示文件名、**下载**、关闭和缩放工具。支持放大、缩小、**适合窗口**，放大后可以滚动或拖动查看图片。
- 点击关闭按钮、空白背景或按 Escape 关闭图片，底层工作项快速预览仍然保留；焦点回到打开图片的入口。
- 非图片附件的文件名链接保留 Ctrl／⌘ 点击和新标签页操作。
- 有文件读取权限即可预览和下载，不要求替换或删除权限；只读工作项也可通过 **⋯** 菜单或大图工具栏中的**下载**保存附件。
- 文件删除、替换或切换工作项后关闭当前图片，避免显示过时内容。

预览使用原有受保护附件地址和对象存储签名链路，未新增公开文件地址、数据库字段或上传流程。SVG、PDF、Office 等附件仍按原文件方式打开。

## 替换与删除

右侧 **⋯** 菜单提供**下载**；有相应编辑权限时还提供替换文件和删除附件。空附件行不显示下载项：

- **替换文件**：上传成功后删除旧文件，该行只保留新文件；失败或取消上传时旧文件不变。
- **删除附件**：确认后同时删除附件行和其中的文件。尚未完成的关联上传也会取消，迟到的完成请求不能把文件重新加回。
- 空附件行也可直接删除。
- 删除与替换沿用文件权限：文件创建者或项目管理员可操作有文件的行；其他成员可以按已有权限修改名称、上传空行，但不能通过删除整行或替换来删除他人的文件。

删除使用现有文件删除机制，行与文件在同一数据库事务中标记删除。客户端使用服务端返回的实际文件 ID 同步列表，失败时保持原数据，迟到的上传和读取响应不会恢复已删除文件。

## 模板库

**附件模板库**按钮位于顶部**附加**按钮后面，可独立打开，不依赖列表是否展开。模板由同一工作空间的项目共用，只保存模板名与有序的附件名称，不保存文件。

- 可以新建、编辑、删除模板，或将当前附件结构保存为模板。
- 应用模板只追加缺少的附件行，保留已有名称与文件；重复应用不会重复创建同名行。
- 应用后若超过新建行限制则整次拒绝，不部分创建。
- 修改或删除模板不会追溯修改工作项中已应用的附件。
- 模板编辑弹窗中的点击、输入和关闭不会误关闭底层工作项快速预览。

## 权限与上传错误

模板库供活跃工作空间管理员、成员管理。附件行管理要求相应项目权限；访客可按已有文件上传权限直接上传并查看自己自动创建的附件行，但不会因此获得命名、模板或整行删除权限。

单文件大小沿用实例配置，默认 1GB（1073741824 字节）。错误提示保留文件实际字节数、配置上限、HTTP 状态及安全的接口错误说明，区分权限、网络、存储和大小限制。

## 接口与既有文件

正式工作项的直接上传、指定行上传、外部 API 与其它已绑定工作项的上传入口均复用同一种附件行。文件存储仍使用 `FileAsset`，行使用现有 `IssueAttachmentSlot`，这是行与文件的关联，不再提供另一套文件列表。

删除附件行的响应为：

```json
{
  "slot_id": "<row UUID>",
  "deleted_attachment_ids": ["<file UUID>"]
}
```

上传预签名与完成响应提供 `attachment_slot_id` 和 `attachment_slot: {id, name, sort_order}`。完成上传返回 HTTP 200，并附带实际被替换的 `deleted_attachment_ids`；重复确认当前文件保持幂等，删除集合为空。前端用服务端返回的真实行信息立即显示上传结果，不依赖额外列表请求成功。

迁移 `0132_unify_issue_attachment_rows` 为有效的既有工作项文件补齐附件行，保留文件 ID、URL、原文件及创建者；不会因数量超过 50 而丢弃历史文件。已有有效命名行保持原名称。描述图片、评论和草稿存储不受此迁移影响。

部署时更新 API 与前端并执行数据库迁移；仓库的 AIO 镜像启动流程会自动运行迁移。对于仍未完成的旧上传，完成接口会按统一规则处理，不能恢复已经删除或被替换的文件。
